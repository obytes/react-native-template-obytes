# SQLite Database Layer — Design Spec

**Date:** 2026-05-24  
**Status:** Approved  
**Scope:** Database infrastructure for expense/income management app (budgets, categories, transactions)

---

## Overview

Implement a local SQLite database layer using **expo-sqlite + Drizzle ORM** with the Repository pattern. Queries and commands are separated at the file level (CQRS-style). The database is exposed to the React tree via a provider/context, keeping the data layer decoupled from React lifecycle.

---

## Tech Stack

| Layer | Choice |
|---|---|
| SQLite driver | `expo-sqlite` |
| ORM / query builder | `drizzle-orm` |
| Migrations | `drizzle-kit generate` → SQL files → `expo-sqlite migrator` |
| Type safety | Drizzle infers TypeScript types from schema |

## Schema

All IDs are UUIDs stored as `text`. Monetary amounts are `real` (always positive). Dates are ISO 8601 strings (`text`): date-only for `start_date`/`end_date`, full datetime for `date` on transactions and all `created_at`/`updated_at` fields.

### `budget_category`

| Column | Type | Notes |
|---|---|---|
| `id` | text PK | UUID |
| `name` | text | e.g. "Comida", "Salario" |
| `type` | text | `'expense' \| 'income'` |
| `icon` | text nullable | icon name |
| `created_at` | text | ISO datetime |

### `budget`

| Column | Type | Notes |
|---|---|---|
| `id` | text PK | UUID |
| `budget_category_id` | text FK → budget_category | cascade delete |
| `name` | text | e.g. "Comida Mayo 2026" |
| `amount` | real | allocated amount |
| `period` | text | `'monthly' \| 'weekly' \| 'yearly'` |
| `start_date` | text | ISO date |
| `end_date` | text nullable | ISO date |
| `created_at` | text | ISO datetime |
| `updated_at` | text | ISO datetime |

### `transaction`

| Column | Type | Notes |
|---|---|---|
| `id` | text PK | UUID |
| `budget_id` | text FK → budget | cascade delete |
| `title` | text | short label |
| `amount` | real | always positive |
| `notes` | text nullable | free text |
| `date` | text | ISO datetime of the transaction |
| `created_at` | text | ISO datetime |
| `updated_at` | text | ISO datetime |

**Relationship chain:** `budget_category` → `budget` → `transaction`  
Deleting a budget_category cascades to its budgets, which cascade to their transactions.

## DB Client

`client.ts` exports a single `createDatabase()` function that opens the expo-sqlite connection and wraps it with Drizzle. Called once at app startup inside the provider.

```ts
// src/lib/database/client.ts
import { openDatabaseSync } from 'expo-sqlite'
import { drizzle } from 'drizzle-orm/expo-sqlite'
import * as schema from './schema'

export type DrizzleDB = ReturnType<typeof createDatabase>

export function createDatabase() {
  const sqlite = openDatabaseSync('budget-app.db')
  return drizzle(sqlite, { schema })
}
```

## Provider

`DatabaseProvider` initializes the DB, runs pending migrations, then renders children. While migrating it renders `null` (the root splash screen remains visible). Once ready, it instantiates all repositories and exposes them via context.

```ts
// src/lib/database/provider.tsx
const DatabaseContext = createContext<DatabaseContextValue | null>(null)

export function DatabaseProvider({ children }: { children: React.ReactNode }) {
  const [repositories, setRepositories] = useState<DatabaseContextValue | null>(null)

  useEffect(() => {
    const db = createDatabase()
    runMigrations(db).then(() => {
      setRepositories({
        budgetCategories: new BudgetCategoryRepository(db),
        budgets: new BudgetRepository(db),
        transactions: new TransactionRepository(db),
      })
    })
  }, [])

  if (!repositories) return null

  return (
    <DatabaseContext.Provider value={repositories}>
      {children}
    </DatabaseContext.Provider>
  )
}

export function useDatabase(): DatabaseContextValue {
  const ctx = useContext(DatabaseContext)
  if (!ctx) throw new Error('useDatabase must be used inside DatabaseProvider')
  return ctx
}
```

`DatabaseProvider` is mounted in `src/app/_layout.tsx`, wrapping the whole app.

## Repository Pattern

Each entity has three files:

### `*.queries.ts` — pure read functions
Pure functions that take `db` as first argument. No side effects.

```ts
// budget.queries.ts
export const findAllBudgets = (db: DrizzleDB) =>
  db.select().from(budgets).all()

export const findBudgetById = (db: DrizzleDB, id: string) =>
  db.select().from(budgets).where(eq(budgets.id, id)).get()

export const findBudgetsByCategory = (db: DrizzleDB, categoryId: string) =>
  db.select().from(budgets).where(eq(budgets.budgetCategoryId, categoryId)).all()
```

### `*.commands.ts` — pure write functions
Pure functions that take `db` as first argument. Return the inserted/updated row or void.

```ts
// budget.commands.ts
export const createBudget = (db: DrizzleDB, data: NewBudget) =>
  db.insert(budgets).values(data).returning().get()

export const updateBudget = (db: DrizzleDB, id: string, data: Partial<NewBudget>) =>
  db.update(budgets).set(data).where(eq(budgets.id, id)).returning().get()

export const deleteBudget = (db: DrizzleDB, id: string) =>
  db.delete(budgets).where(eq(budgets.id, id)).run()
```

### `index.ts` — Repository class
Wraps the pure functions, fixing `db`. This is what consumers receive from `useDatabase()`.

```ts
// repositories/budget/index.ts
export class BudgetRepository {
  constructor(private db: DrizzleDB) {}

  // queries
  findAll = () => findAllBudgets(this.db)
  findById = (id: string) => findBudgetById(this.db, id)
  findByCategory = (categoryId: string) => findBudgetsByCategory(this.db, categoryId)

  // commands
  create = (data: NewBudget) => createBudget(this.db, data)
  update = (id: string, data: Partial<NewBudget>) => updateBudget(this.db, id, data)
  delete = (id: string) => deleteBudget(this.db, id)
}
```

The same pattern applies to `TransactionRepository` and `BudgetCategoryRepository`.

## Shared Types

`repositories/_shared/types.ts` exports inferred types from the Drizzle schema so features don't import from the schema directly:

```ts
import type { createDatabase } from '../../client'
import { budgetCategories, budgets, transactions } from '../../schema'

export type DrizzleDB = ReturnType<typeof createDatabase>

export type BudgetCategory = typeof budgetCategories.$inferSelect
export type NewBudgetCategory = typeof budgetCategories.$inferInsert

export type Budget = typeof budgets.$inferSelect
export type NewBudget = typeof budgets.$inferInsert

export type Transaction = typeof transactions.$inferSelect
export type NewTransaction = typeof transactions.$inferInsert
```

## Migrations

`drizzle-kit` generates `.sql` files from the schema. These are bundled into the app and run at startup by expo-sqlite's migrator:

```ts
// migrations/index.ts
import { migrate } from 'drizzle-orm/expo-sqlite/migrator'
import migrations from './migrations' // bundled via babel plugin

export function runMigrations(db: DrizzleDB) {
  return migrate(db, migrations)
}
```

`drizzle.config.ts` at the repo root points to `src/lib/database/schema/index.ts` as source and `src/lib/database/migrations/` as output. Running `pnpm drizzle-kit generate` produces the SQL files.

## Integration with Features

Features consume the repositories via `useDatabase()` and wrap them with React Query for caching and loading state:

```ts
// src/features/budget/api.ts
export const useBudgets = () => {
  const { budgets } = useDatabase()
  return useQuery({
    queryKey: ['budgets'],
    queryFn: () => budgets.findAll(),
  })
}
```

The database layer has no knowledge of React Query — it only exposes plain async functions.

---

## What's Out of Scope

- UI components for budgets, transactions, and categories
- React Query hooks for each feature (defined per-feature, not in the DB layer)
- Authentication or multi-user support
- Data export / backup
