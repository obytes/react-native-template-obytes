Enfoques de arquitectura

¿Dónde y cómo se almacenan las monedas?

A

Tabla en SQLite (Recomendado)

Se crea una tabla currency en la DB con code, name, symbol, exchange_rate, is_enabled, is_default. La tabla se pre-puebla en una migración. La cuenta tiene un FK a currency. Sigue exactamente el mismo patrón que account_category y account.

Pros

  • Consistente con el patrón existente
  • FK garantiza integridad referencial
  • Fácil de extender después

Cons

  • Requiere nueva migración
  • Más archivos (schema, repository, queries)
B

MMKV / Estado persistido

El catálogo de monedas se guarda en MMKV (como el auth store). La tabla account agrega solo un campo currency_code (texto, sin FK).

Pros

  • No requiere migración SQL compleja
  • Lectura rápida sin queries

Cons

  • No hay FK → datos inconsistentes posibles
  • Rompe el patrón del proyecto
  • Difícil de consultar junto a cuentas
C

Catálogo estático en código + DB mínima

El catálogo completo de monedas vive en un archivo TypeScript. Solo las monedas habilitadas se guardan en DB (tabla ligera). Account guarda currency_code como texto.

Pros

  • No hay que migrar el catálogo completo
  • Fácil de actualizar el catálogo sin migración

Cons

  • Lógica dividida entre código y DB
  • Sin FK real entre account y currency
