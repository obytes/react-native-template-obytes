## What: Database Layer (`src/lib/database/`)

Local SQLite database using **expo-sqlite + Drizzle ORM** with the Repository pattern. Schema: `BudgetCategory → Budget → Transaction` (cascade deletes).

```
src/lib/database/
├── client.ts                        # createDatabase() singleton + DrizzleDB type
├── provider.tsx                     # DatabaseProvider + useDatabase() hook
├── schema/
│   ├── budget-category.ts           # budget_category table
│   ├── budget.ts                    # budget table (FK → budget_category)
│   ├── transaction.ts               # transaction table (FK → budget)
│   └── index.ts
├── migrations/
│   ├── 0000_gorgeous_dragon_man.sql # Generated by drizzle-kit
│   ├── index.ts                     # runMigrations(db) — runs at app startup
│   └── meta/                        # drizzle-kit journal + snapshots
└── repositories/
    ├── _shared/types.ts             # DrizzleDB, Budget, NewBudget, etc.
    ├── budget-category/
    │   ├── budget-category.queries.ts   # Pure read functions
    │   ├── budget-category.commands.ts  # Pure write functions
    │   └── index.ts                     # BudgetCategoryRepository class
    ├── budget/
    │   ├── budget.queries.ts
    │   ├── budget.commands.ts
    │   └── index.ts                     # BudgetRepository class
    └── transaction/
        ├── transaction.queries.ts
        ├── transaction.commands.ts
        └── index.ts                     # TransactionRepository class
```

## How: Key Patterns

- **Create features**: New folder in `src/features/[your-feature]/` with screens, components, API hooks
- **Add routes**: Create files in `src/app/` (file-based routing)
- **Forms**: Use TanStack Form + Zod (see `src/features/auth/components/login-form.tsx`)
- **Data fetching**: Use React Query (see `src/features/feed/api.ts`)
- **Global state**: Use Zustand (see `src/features/auth/use-auth-store.tsx`)
- **Local DB**: Use `useDatabase()` hook — never import repository classes directly
- **Schema changes**: Edit schema files → run `pnpm db:generate` → commit the new `.sql` migration
- **Styling**: NativeWind/Tailwind classes (see `src/components/ui/button.tsx`)
- **Key-value storage**: Use MMKV via `src/lib/storage.tsx` for tokens/settings
- **Imports**: Always use `@/` prefix, never relative imports

## How: Essential Rules

- ✅ **DO** use absolute imports: `@/components/ui/button`
- ✅ **DO** follow feature-based structure: `src/features/[name]/`
- ✅ **DO** use TanStack Form for forms (not react-hook-form)
- ✅ **DO** use MMKV storage for key-value data (tokens, settings)
- ✅ **DO** use `useDatabase()` for all SQLite access — never instantiate repositories directly
- ✅ **DO** run `pnpm db:generate` and commit the `.sql` file after every schema change
- ✅ **DO** use EAS Build for production: `pnpm build:production:ios`
- ✅ **DO** prefix env vars with `EXPO_PUBLIC_*` for app access
- ❌ **DO NOT** modify `android/` or `ios/` directly (use Expo config plugins)
- ❌ **DO NOT** add new columns/tables without running `pnpm db:generate`
